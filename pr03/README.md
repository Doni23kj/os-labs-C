# ПР-3 (вариант C): мини-shell на C

## Сборка и запуск
```bash
make            # gcc -Wall -Wextra, без предупреждений
./minishell     # интерактивно
make test       # автотест: pipe, <, >, &, cd, отсутствие зомби
```
Возможности: `fork + execvp + waitpid`; встроенные `cd`, `exit`, `jobs`, `fg`, `bg`; конвейеры любой длины (`pipe` + `dup2`);
перенаправления `<`, `>`; фоновый запуск `&`; обработчик `SIGCHLD` убирает зомби;
Ctrl+C завершает только дочернюю команду (оболочка игнорирует `SIGINT`, потомки сбрасывают его в `SIG_DFL`, у каждого конвейера своя группа процессов и он получает терминал через `tcsetpgrp`).
Ограничение: нет `>>`, `2>`, подстановок и экранирования (кавычки `"..."` поддерживаются).

## Как это устроено (для защиты)
1. **Группы процессов.** Каждый конвейер — отдельная группа (`setpgid`); `Ctrl+C` терминал шлёт группе foreground, а не оболочке.
2. **SIGCHLD.** Обработчик в цикле вызывает `waitpid(-1, WNOHANG|WUNTRACED)` и обновляет таблицу заданий. Во время создания процессов
   сигнал заблокирован (`sigprocmask`), иначе обработчик мог бы убрать ребёнка до записи его PID в таблицу (гонка).
   Foreground-ожидание — через `sigsuspend`, который атомарно разблокирует сигнал и засыпает.
3. **Pipe.** В каждом ребёнке после `dup2` закрываются **все** концы pipe, в родителе — write-конец сразу после `fork`;
   иначе читатель (`wc`) никогда не получит EOF.
4. **Нет зомби.** Фоновые задания собираются `SIGCHLD`; `jobs` и приглашение показывают `Done`.

## Показать под strace (вывести в `strace_ls_wc.txt`)
```bash
echo 'ls | wc -l' | strace -f -o strace_ls_wc.txt -e trace=process,pipe2,dup2,execve,close,wait4,read,write ./minishell
```
Что должно быть видно в ожидаемом порядке: `pipe2` → два `clone` (fork) → в детях `dup2(fd,1)` / `dup2(fd,0)`, `close` лишних дескрипторов,
`execve("ls")`, `execve("wc")` → `write` из `ls` в pipe → `read` в `wc` → `exit_group` → `wait4` в родителе (через `SIGCHLD`).
Приложите вывод и пометьте строки комментариями.

## Контрольные вопросы
* *Почему fork возвращает два значения?* — Он возвращается дважды: в родителе (PID ребёнка) и в ребёнке (0), у каждого своя копия адресного пространства.
* *Что будет при exec без fork?* — Образ текущего процесса заменится новой программой, управление не вернётся; для оболочки это значит «оболочка исчезла».
