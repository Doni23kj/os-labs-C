## 1. Параллельная сумма 10⁸ элементов (`sum_threads.c`)
Каждый поток суммирует свой диапазон в локальную переменную и записывает результат один раз (чтобы сам алгоритм не страдал от false sharing).

Построить график «N → ускорение» (по `sum_threads.csv`; matplotlib/gnuplot/LibreOffice).

**Где и почему рост прекращается** (шаблон вывода — подтвердите своими цифрами):
* при N > числа логических ядер (`nproc`) новые потоки не получают собственных ядер — ускорение больше не растёт, добавляются лишь накладные расходы на планирование;
* сумма массива — операция с низкой арифметической интенсивностью: ограничением становится пропускная способность памяти (memory-bound), а не ядра; обычно ускорение насыщается раньше, чем число ядер;
* гиперпоточность даёт меньше, чем физическое ядро.

## 3. False sharing (`false_sharing.c`)
Два потока увеличивают свои счётчики. Если счётчики лежат в одной 64-байтной кэш-линии, ядра вынуждены перекидывать линию друг другу (протокол когерентности MESI),
хотя логически данные независимы. При разнесении на 64 байта запись идёт в разные линии.
| раскладка | время, с (медиана из 3) |
|---|---|
| рядом (одна линия) | |
| разнесены на 64 Б | |

Ожидание на ≥2 ядрах: «рядом» в 2–10 раз медленнее. На 1 ядре разницы нет (потоки не работают одновременно).

## 4. Поток и процесс на уровне ядра Linux
В Linux нет отдельной сущности «поток»: и поток, и процесс — это `task_struct`, создаваемый системным вызовом `clone()`. Разница только в флагах:
* поток: `CLONE_VM | CLONE_FS | CLONE_FILES | CLONE_SIGHAND | CLONE_THREAD | …` — общие адресное пространство, дескрипторы, обработчики сигналов, общий TGID (то, что `getpid()` возвращает всем потокам);
* процесс (`fork`): флагов общего доступа нет — копия адресного пространства (COW) и таблицы дескрипторов.
Третья строка в `spawn_cost` (`clone(CLONE_VM|SIGCHLD)`) — промежуточный случай: общая память, но отдельный «процесс».
Подтвердить: `strace -f -e trace=clone,clone3 ./spawn_cost 5` — сравните флаги у `pthread_create` и `fork`.

## Вывод: когда потоки, когда процессы
* Потоки — общие данные, дешёвое создание, нужна синхронизация (ПР-6); хороши для CPU-bound на C и для I/O-bound везде.
* Процессы — изоляция (падение/порча памяти не влияют на другие), обход GIL в CPython; дороже создание и обмен данными (ПР-7).
